# Real Match Calibration Dataset

Alpha 0.5.8.1 adds a real-match calibration workflow for the Hattrick Midfield Rating
Engine v1.

The workflow records played matches, freezes the lineup and context used for the
prediction, stores the official Hattrick midfield rating, and measures the error of
`midfield-v1` without changing model parameters.

## Boundaries

This feature does not tune the model. It does not modify optimizers, internal sector
ratings, probability calculations, expected goals, Squad, Planner or Match accordion
layout code.

Calibration data is evidence. Parameter changes must happen in a future model-versioned
milestone after the dataset is large enough for review.

## Package

```text
engine/hattrick_ratings/calibration/
  models.py
  rating_input.py
  quality.py
  metrics.py
  repository.py
  service.py
  cli.py
```

The package is Qt-independent and belongs to the rating-engine side of the architecture.
The desktop application can call it through services later, but views must not call the
rating calculator directly.

## Record Model

`RealMatchCalibrationRecord` stores:

- record identity and schema version;
- match date, match ID, competition, opponent and venue;
- played/draft/archive status;
- exact formation label;
- frozen lineup snapshot;
- match context snapshot;
- official sector ratings;
- official result metadata;
- observations keyed by model version;
- source and synthetic flags.

The current required official sector is midfield. Defense and attack official sectors
are optional placeholders for future rating engines.

## Lineup Snapshot

Snapshots preserve the state used for the prediction:

- player ID and name;
- slot;
- position;
- side;
- individual order;
- order side where applicable;
- playmaking, winger, passing, defending, scoring, goalkeeping and set pieces;
- form, stamina and experience;
- specialty;
- missing-field warnings;
- snapshot source and timestamp.

Later roster edits do not mutate saved calibration records.

## Validation

Finalization requires:

- record ID;
- played match;
- non-future match date;
- formation;
- lineup snapshot;
- unique starters;
- official midfield rating.

Missing player form, stamina or skill fields are warnings, not blockers, because
`midfield-v1` has explicit conservative assumptions for those values.

Data quality is classified as:

- `complete`;
- `usable_with_assumptions`;
- `incomplete`;
- `invalid`.

## Official Rating Input

Official Hattrick ratings are stored as canonical quarter steps through
`HattrickRating`.

Accepted input formats:

- exact quarter decimals, such as `5`, `5.25` or `5.50`;
- named Hattrick level/sublevel labels, such as `inadequate low`;
- serialized `HattrickRating` dictionaries.

Arbitrary decimals, negative values and unknown labels are rejected.

## Observations

When a record is finalized, the service generates one observation for the current model
version:

- predicted midfield;
- official midfield;
- signed error;
- absolute error;
- exact match flag;
- within 0.25 flag;
- within 0.50 flag;
- confidence;
- warning codes;
- timestamps.

Re-finalizing the same record recalculates the observation for that model version while
preserving its stable observation ID.

## Metrics

Reports include:

- sample count;
- exact accuracy;
- accuracy within 0.25;
- accuracy within 0.50;
- mean absolute error;
- median absolute error;
- signed bias;
- maximum and minimum error;
- confidence distribution;
- warning distribution.

Segments are generated by:

- formation;
- home/away;
- team attitude;
- known or unknown team spirit;
- prediction confidence;
- unsupported order warnings.

## CLI Workflow

Run commands from the repository root.

```powershell
.\.venv\Scripts\python.exe -m engine.hattrick_ratings.calibration --store .ht_coach_calibration\real_match_records.json list-records
.\.venv\Scripts\python.exe -m engine.hattrick_ratings.calibration --store .ht_coach_calibration\real_match_records.json validate-record fixtures\hattrick\calibration\synthetic_real_match_records.json
```

To add a single exported record JSON:

```powershell
.\.venv\Scripts\python.exe -m engine.hattrick_ratings.calibration --store .ht_coach_calibration\real_match_records.json add-record path\to\record.json
```

To finalize and calculate observations:

```powershell
.\.venv\Scripts\python.exe -m engine.hattrick_ratings.calibration --store .ht_coach_calibration\real_match_records.json finalize-record record-id
```

To recalculate and report:

```powershell
.\.venv\Scripts\python.exe -m engine.hattrick_ratings.calibration --store .ht_coach_calibration\real_match_records.json recalculate --model midfield-v1
.\.venv\Scripts\python.exe -m engine.hattrick_ratings.calibration --store .ht_coach_calibration\real_match_records.json report --model midfield-v1
```

To export/import validation fixtures:

```powershell
.\.venv\Scripts\python.exe -m engine.hattrick_ratings.calibration --store .ht_coach_calibration\real_match_records.json export --model midfield-v1 --output validation_export.json
.\.venv\Scripts\python.exe -m engine.hattrick_ratings.calibration --store .ht_coach_calibration\real_match_records.json import validation_export.json
```

## Persistence

The repository stores a versioned JSON object:

```json
{
  "schema_version": 1,
  "records": []
}
```

Malformed stores, unsupported future schema versions and invalid individual records are
handled without crashing. Invalid records are skipped on load.

The CLI default store is `.ht_coach_calibration/real_match_records.json`. A future
desktop integration should place this under the HT Coach application data directory.

## Synthetic Fixture

`fixtures/hattrick/calibration/synthetic_real_match_records.json` is intentionally
synthetic. It exists to document the schema and support workflow validation; it must not
be treated as real calibration evidence.
